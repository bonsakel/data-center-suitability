# ArcGIS Pro analysis checklist

The inputs in this guide are generated by `scripts/01_clean_opposition.py` through `scripts/04_summary_stats.py`. ArcGIS Pro is not available in this workspace, so these steps are a checklist for running and exporting the GIS analyses.

## 1. Add the prepared layers

1. Open ArcGIS Pro and create a project in `arcgis/`.
2. Add `data/clean/county_summary.gpkg`. Select the `counties` layer.
3. Add `data/clean/registry_county_joined.csv` and `data/clean/opposition_county_joined.csv` as tables.
4. For each CSV, use **XY Table To Point**:
   - Facilities: X = `longitude`, Y = `latitude`, coordinate system = WGS 1984.
   - Opposition: X = `lng`, Y = `lat`, coordinate system = WGS 1984.
   - Export the resulting point layers to a project geodatabase.
5. Add `data/clean/proposed_nearest_operating.csv` for comparison with the Near tool. It contains geodesic distances in kilometers and miles calculated by the Python pipeline.
6. Save a copy of the project before running tools. Do not edit files in `data/raw/`.

## 2. Map facilities by status

1. Open **Symbology** for the facility point layer and choose **Unique Values** on `status_clean`.
2. Use distinct colors for operating, proposed, permitted, under construction, and cancelled sites. Include all five values in the legend.
3. Use a national extent with Alaska and Hawaii insets. Keep all point layers in WGS 1984 for display; project analysis layers before using distance or density tools.
4. Export a first map as `arcgis/facilities_by_status.png`.

## 3. Kernel Density

Run this analysis separately for operating facilities, planned facilities, and opposition records.

1. Open **Analysis > Tools > Kernel Density**.
2. Use one point layer for each run. For the planned layer, select `proposed`, `permitted`, and `under_construction`; do not include cancelled records.
3. Use a projected coordinate system suitable for the map area. A lower-48 analysis can use USA Contiguous Albers Equal Area; make separate Alaska and Hawaii inset analyses rather than measuring those states in a lower-48 projection.
4. Set the population field to `NONE` so each point has equal weight.
5. Use the same cell size and search radius across the three comparable maps. Record the chosen values in the map layout and methods log; inspect the scale before settling on them.
6. Use a sequential color ramp and a shared legend for all three outputs.

## 4. Getis-Ord Gi* hot spots

Use the hexagon workflow when available because county counts are sparse.

1. Open **Generate Tessellation** and create hexagons in a projected coordinate system. Use a consistent hexagon width for the study area and record it.
2. Use **Summarize Within** to count opposition points in each hexagon. Repeat for planned facility points if a second hot-spot layer is useful.
3. Run **Incremental Spatial Autocorrelation** on the hexagon counts to inspect meaningful distance bands.
4. Open **Hot Spot Analysis (Getis-Ord Gi*)**. Input the hexagon layer, analysis field = the count field, spatial relationship = fixed distance band, distance band = a supported distance found in the prior step, and apply False Discovery Rate correction.
5. Map Gi_Bin values with the ArcGIS hot/cold spot ramp. Explain that a significant cluster is spatial clustering of these records, not proof of cause.
6. If hexagon analysis is unavailable, use counties as the analysis features and county opposition record counts as the analysis field. Note the change in scale and sparsity.

## 5. Near distance to an operating facility

1. Select proposed facilities from the registry points using `status_clean = proposed`.
2. Run **Near** with the proposed layer as input and operating facilities as near features. Choose the **Geodesic** method so the result can be compared with the pipeline's Earth-surface distance.
3. Export the proposed points with `NEAR_DIST` and `NEAR_FID`.
4. Compare a sample of facility IDs against `data/clean/proposed_nearest_operating.csv`. The Python distance is in kilometers; convert ArcGIS distance to the same units before comparing.
5. Record any ties or meaningful differences. Do not substitute county-centroid distances for facility-point distances.
6. Symbolize the proposed facility and its nearest operating facility, then draw a line between the two points for a few examples. Avoid drawing every line on the national map.

## 6. Bivariate map: facilities and opposition rate

1. Use the county summary layer and filter out counties where `planned_count` is zero. Their opposition-per-planned-facility rate is undefined, not zero.
2. Classify `planned_count` and `opposition_per_planned_facility` into three documented classes. Use the same method for each variable and avoid allowing the many zero-planned counties to define the rate legend.
3. Combine the two classes into a 3-by-3 bivariate color scheme.
4. Add a note that the map shows spatial association in monitored records and does not establish causation.

## 7. Concern small multiples

1. Use `data/clean/county_concern_counts.csv` and join its `GEOID` to the county layer.
2. Create separate maps for water, grid/energy, noise, and ratepayer concern mentions.
3. Use the same map extent, scale, and count classes across panels. Add a fifth panel only if the resulting map remains readable.
4. Label these as concern tags in opposition records; one record can have several tags.

## 8. Export and compare

1. Export the facility-status map, the three density maps, the Gi* map, the Near examples, the bivariate map, and concern small multiples into `arcgis/`.
2. Use the same map extent and accessible color choices when comparing panels.
3. Save a short note with the exact tool settings, output dates, and any ArcGIS results that differ from Python.
4. Use the maps and the precomputed CSV tables in the poster and StoryMap. Do not describe the maps as causal evidence.
